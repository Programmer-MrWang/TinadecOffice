# 工程推进方式

## 阶段0：档案建立

本轮完成总图归档、55个模块目录与初始源码事实、模块图、状态/TODO、模板和总索引工具。文档目录就绪不代表功能审计或开发完成。

## 阶段1：逐模块功能审计

以各模块001任务开始，把聚合功能逐项拆开；建立真实入口、行为、权限、失败/取消、持久化/恢复和测试证据。先明确缺口，再决定目标；任何完成标记保留可查证据。

可优先从APP-CODE的生产worker问题复验，或CORE-DMAEA运行主链开始深入分析；这是建议顺序，不自动启动业务修改。

## 阶段2：拆分实现任务与跨模块依赖

已确认缺口拆成可评审、可实施、可独立验收的任务。稳定ID连到Feature ID；写清主责、协作模块、真实依赖和验收条件。范围选择进入决策记录后再转实现，避免把所有桩和平台边界默认开发成目标。

## 阶段3：实现与定向验收

围绕一项具体任务完成设计、代码、必要测试、运行证据和文档。相关检查通过且无未解决问题时推进任务，不重复扩大测试来替代真实目标验收。

## 阶段4：模块与跨模块整体验收

对已经完成逐功能分析的模块跑适用成功/失败/权限/恢复矩阵，再验证跨模块流程；数据库、真实模型、安装版和平台内核结果分别记录，不用一个总绿概括。

## 状态更新

任务在模块TODO更新，功能在STATUS更新；证据放03-evidence或链接既有报告。然后运行reindex生成总TODO/进度/模块索引。[查看总TODO](MASTER-TODO.md)。
